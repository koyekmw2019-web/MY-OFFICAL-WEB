# YE KUN Official Website — v7.86.5 Personal Exam Coach

**Brand:** STUDYING WITH YE KUN  
**Base:** `YEKUN_v7.86.4_JLPT_Dynamic_Countdown_Corrected.zip` (the approved JLPT target + dynamic countdown hotfix).  
**Scope:** Student Dashboard only. No new public pages. Existing mock exam access/payment/YKCR rules are retained.

## 1. What the user sees

Open **Student Dashboard → My Learning Pro → select one exam** (TRUCK, TAXI, BUS, 自動車整備, 普通自動車, 二輪, 原付, JLPT N1–N5). Under that selection, a new **🎯 My Exam Coach** panel loads the signed-in user's own coaching results on demand.

- After **one NEW server-verified mock exam**, the panel shows correct/total and practice accuracy by the **trusted sections the saved checkpoint can prove**.
- JLPT: Vocabulary / Grammar / Reading / Listening.
- TRUCK/TAXI/BUS/自動車整備: Theory / Practical.
- 普通自動車 / 二輪 / 原付: **overall practice only**. The current canonical source has no trusted question-topic classification; the website does not invent it.
- Lowest practice accuracy is shown first. A single mock exam gives a **practice priority**, NOT a reliable diagnostic conclusion about proficiency.
- Optional *My planned exam date* is independently saved per student and exam type; this is a **user-selected date, not an official examination schedule**. It builds a bounded 7-day (or fewer remaining days) study routine. No user-supplied date modifies JLPT official countdown.
- Wrong Answer Review and all existing dashboards stay intact. The coach does not grant or consume any exam attempts.

## 2. Critical: apply database migration before using the feature

**NEW MIGRATION REQUIRED:** `netlify/database/migrations/20261110190000_v7865_exam_coach.sql`

This creates two additive private tables:
- `exam_coach_topic_results`: an account-scoped per-attempt aggregate (topic ID, correct count, total), saved from the SERVER's previously validated checkpoint when an attempt is submitted.
- `exam_coach_target_dates`: account-scoped, user-selected exam dates.

**Apply this SQL using the existing Netlify Database migration workflow to STAGING first, then production after verification.** Back up the database before migration. Do not assume that GitHub Push automatically executes every migration in your Netlify setup. No new environment variables are necessary if the existing Netlify Database and Identity integrations work.

The submit function's new INSERT is **best-effort**: if the migration is missing, the exam result is still submitted but no new coaching snapshot is stored; the Coach endpoint will report data unavailable. Therefore apply migration *before* students take new exams.

**Old attempts:** Previous exam checkpoints were deleted after submission. Their verified topic-level answer snapshots cannot be recreated from stored totals. Existing historical overall scores and saved wrong answers remain available in the older panels. Students must take a **new eligible mock exam after deployment** to get trustworthy topic-level coaching. Do not bypass the existing one-free-attempt/student/paid-access rules.

## 4. Safe rollout

1. Make a new Staging branch in the *existing* GitHub Desktop repository. Copy contents of this ZIP into the current repo folder without removing `.git`, then commit/push to Staging.
2. Apply migration to STAGING Database using the current Netlify Database migration procedure.
3. In Netlify, verify `npm run build` succeeds and the `dist` publish directory exists; ensure `assets/identity.bundle.js` is generated by esbuild.
4. Login as a Student; select TRUCK, verify coach shows no fabricated data for older attempts, take one **authorized** test attempt, confirm topic evidence appears. Test JLPT and a license exam separately if feasible.
5. Save a personal exam date, reload and confirm that only this student sees it; login as a different student to check isolation.
6. Test phone layouts at 320px / 390px, then Admin/Payment/YKCR/Exam Regression, Dictionary, Video Class and characters.
7. Only after Staging is verified, merge into main and deploy Production. Back up before the database migration.
